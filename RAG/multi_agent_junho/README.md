# multi agent 설계

## 구축방안
=> multi_agent 구축: 
=> 입력 키워드를 기반으로 llm이 SQL명령어 구성하는 tool 적용 => langchain의 QuerySQLDataBaseTool
=> QuerySQLDataBaseTool 라이브러리이용: from langchain_community.tools.sql_database.tool import QuerySQLDataBaseTool
=> 병렬 실행 에이전트로 구성
=> 특정 키워드(우리은행, <특정 상품명>, 조항(제O조))입력받을 시, 은행명, 조항 등을 DB에서 정확히 조회해서 이를 근거로 답변생성

## langgraph 순서(병렬처리)
사용자 질의 입력받음 => 은행명, 상품이름, 조항, 조항이름 키워드 탐지(이외 키워드는 text 및 context 항목에서 유사 키워드(SQL: LIKE %이자) 추출) => llm에 의한 query문 생성 => query문 결과에 따른 맞춤형 프롬프트 생성(키워드 조합별 prompt 작성) => 각 프롬프트에 기반한 llm응답 생성

## 순서항목별 상세사항
- 사용자 질의 입력받음: 사용자가 채팅으로 은행상품에 대해 질문받음 (예: 국민은행 대출 금리는 어떻게 되나요?, 우리은행 예금 상품에는 어떤 것이 있나요?)

- 은행명, 상품이름, 조항, 조항이름 키워드 탐지: 우리은행 기업간 e-구매 전자결제서비스(은행명=우리은행, 상품이름=기업간 e-구매 전자결제서비스 조건으로 SQL조회), 국민은행 KB골든라이프 공사주택연금론 확정기간용 추가약정서 제4조(은행명=국민은행, 상품이름=KB골든라이프 공사주택연금론 확정기간용 추가약정서, 조항=제4조)

- llm에 의한 query문 생성: 사용자의 입력 키워드에 따라 심도있게 대응해야 함!! => 상품이름에서 "KB공무원연금평생안심통장_특약"인데, 사용자가 "KB공무원연금평생안심통장", "공무원연금평생안심통장", "공무원 연금 평생 안심 통장" 으로 입력할 경우에도 "KB공무원연금평생안심통장_특약"에 대한 내용이 검색되어야 함, 조항에서는 "제n조"나 "n"으로 나오는데, 데이터가 "n"인 경우 사용자 입력이 "제n조"라고 입력하면, 조항 컬럼에서 n을 포함하는 방식으로 query 구성(LIKE %1)

- query문 결과에 따른 맞춤형 프롬프트 생성(키워드 조합별 prompt 작성): 사용자는 상품에 대한 설명뿐만 아니라, 상품에 대한 내용(이자, 기간, 가입대상 등)에 대해서 질의하는 경우가 있음. 이 경우 해당 키워드를 추출하면, 상품이름이 여러개 나오거나, 상품이름이 안 나옴 => text와 context에서 LIKE query문으로 키워드를 추출하거나, application에서 은행명, 상품이름을 선택할 수 있는 select bar를 제공하여, 답변 정확도 향상과 사용자 편의를 도모하는 것도 고려할 수 있음

- 각 프롬프트에 기반한 llm응답 생성: apllication에서 사용자 질의와 select bar 항목을 고려하여 프롬프트를 구성하고, 이에 기반한 llm응답 생성

## 전체 아키텍쳐 개요
[User Query]
   ↓
[CoordinatorAgent]
   ├─ KeywordAnalyzer → 키워드 유형 탐지 (은행명 / 상품명 / 조항 등)
   ├─ DBMatcher → DB 내 유사 항목 탐색 (fuzzy match, cosine similarity 등)
   ├─ If match:
   │     → DBAgent(SQL로 직접 조회)
   └─ Else:
         → TextSearcherAgent(전체 text 컬럼에서 의미 유사도 검색)
   ↓
[AnswerAgent] → 사용자 친화적으로 설명

## 구현된 기능(2025-10-23 기준)
- 사용자가 질의를 입력받음
- 입력받은 키워드를 바탕으로 은행명, 상품이름, 조항 탐지
